# 项目上下文、事实账本与声线基线

## 1. 权威材料

只把用户最新编辑后的文本视为当前底稿。先读取用户明确指定的 Notion 页面、文件、章节与人物资料；不要用对话摘要代替可读取原文。

冲突时使用以下顺序：

1. 用户当次要求和最新正文；
2. 用户指定的项目资料与已确认设定；
3. 用户同一作品的成稿；
4. 当前任务实际查读的原作；
5. 已核验的研究材料；
6. 模型生成内容。

旧模型草稿、被用户删除的句子和曾经使用过的情节不是事实。

## 2. 五栏事实账本

| 分类 | 含义 | 处理 |
|---|---|---|
| 已知 | 用户或正文直接确认 | 保持一致 |
| 可推导 | 有充分因果支持但尚未明说 | 谨慎使用，不写成确定设定 |
| 未知 | 资料不足 | 保持空白，不补齐 |
| 禁止 | 用户否定或与最新版本冲突 | 不得恢复 |
| 待核验 | 依赖项目页或外部来源 | 查证后再写 |

为每次删除记录其机制性含义，例如：解释过度、道具便利、心理浅显、人物失真、信息重复、节奏错误、篇幅错配。避免用新措辞恢复同一种失败机制。

## 3. 项目上下文模板

只填写能从材料确认的项；未知处留空。

> 项目/作品：
>
> 当前章节与时间位置：
>
> 当前有效底稿：
>
> 叙述人称与焦点人物：
>
> 本场进入状态：
>
> 尚未解决的压力：
>
> 本场允许改变：
>
> 本场禁止改变：
>
> 必须保留的事实与句子：
>
> 已被用户否定的处理：
>
> 相关人物页/设定页/时间线：
>
> 待核验事实：
>
> 本次交付模式：

长期项目可以把此模板保存为项目页或工作文件，但不要在未经授权的公共仓库中提交包含私人设定、未发表正文、编辑意见或个人信息的上下文文件。

## 4. 人物因果卡

对本场主要人物分别记录：

> 此刻要得到什么：
>
> 此刻要避免什么：
>
> 自我保护方式：
>
> 已知信息：
>
> 误解或盲区：
>
> 能够直接说出的内容：
>
> 绝不会这样说的词或判断：
>
> 压力上升时句法如何改变：
>
> 会注意什么、忽略什么：
>
> 本场结束后留下什么后果：

人物不应因为作者或参考作品知道真相而获得准确判断。

## 5. 声线基线

从用户同一作品中选择至少两个已经确认、且与当前视角相同或相近的成稿片段。不要只提取“冷淡、克制、诗意”等形容词，记录可观察特征：

- 句子长度与停顿方式；
- 叙述者常用和避免的词；
- 描写通常落在动作、物件、身体、空间还是抽象判断；
- 心理进入的深度和入口；
- 对话中谁改口、打断、答非所问或保持沉默；
- 环境描写何时出现，承担什么功能；
- 段尾通常留下事实、动作、判断还是空白；
- 哪些幽默只属于特定人物关系。

建立“正例 + 禁例”：

| 项目 | 正例：作品内部已经成立 | 禁例：用户删除或明确否定 |
|---|---|---|
| 旁白距离 |  |  |
| 对话节奏 |  |  |
| 心理表达 |  |  |
| 环境使用 |  |  |
| 段尾方式 |  |  |
| 人物机智程度 |  |  |

## 6. 技术问题建模

至少回答：

- 当前场面或章节的进入状态是什么；
- 用户希望结束时改变什么；
- 哪项压力推动变化；
- 现稿在哪个层级失效；
- 需要从其他作品研究什么，而不是想模仿谁；
- 哪些内容必须不被解释或解决。

将问题定位到一个或多个层级：

- 事实连续性；
- 人物欲望与因果；
- 社会关系和权力；
- 信息差与知识分配；
- 场面进入、转折、变调与退出；
- 叙述时间和故事时间；
- 视角、心理距离与意识流；
- 对话功能和声音；
- 段落密度与句法节奏；
- 意象、物质世界和母题；
- 留白、悬置和结尾余波。

先修复最高层级。事实错误时不要润色；人物因果错误时不要调整句法；场面没有运动时不要添加环境细节。
