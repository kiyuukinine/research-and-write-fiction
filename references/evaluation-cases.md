# Skill 维护与评测用例

本文件只在维护、发布或测试 Skill 时读取，不用于普通写作任务。

## 1. 触发测试

### 应触发

- “接着这章写下去，但要以我刚改过的版本为准。”
- “参考契诃夫处理尴尬重逢的方法，重写这场戏，并说明怎么化用。”
- “这三版都太像 GPT，别修句子了，重新设计。”
- “读取 Notion 里的人物页，校准两个人的说话方式。”
- “分析这段为什么假深沉，不要直接改。”
- “只润色这两段，不能增加情节。”

### 不应触发

- “把这句话的逗号改对。”
- “写一篇产品发布稿。”
- “总结这篇论文。”
- “解释什么是自由间接引语，不处理具体文本。”
- “把这份表格整理成 CSV。”

### 边界测试

- “写一个完全自由的短故事，不查资料。”
  可以使用结构与反 AI 检查，但不得强制外部查读。

- “分析这段，不要重写。”
  只能输出诊断稿。

- “改这一句，但上一段设定冲突。”
  应先指出阻塞点，不擅自扩大范围。

## 2. 行为测试

### 用例 A：最新编辑优先

输入材料包含旧稿、用户删除后的新版和旧助手摘要。通过标准：

- 只把新版视为底稿；
- 不恢复删除的道具或解释；
- 能说明删除代表的机制性否定；
- 不把助手摘要当设定。

### 用例 B：原文查读

用户要求“参考某作家”。通过标准：

- 实际打开原文与上下文；
- 评论和梗概只用于定位；
- 建立来源卡；
- 无法取得原文时明确说明；
- 不凭记忆生成仿写后再附来源。

### 用例 C：实质化用

来源和目标文本表面情节相似。通过标准：

- 抽取关系、信息、时间或视角机制；
- 至少改变数项实质变量；
- 删除原作专属人物、情节与意象；
- 去掉来源说明后，文本仍属于目标作品；
- 能指出来源究竟改变了哪一处文本运行。

### 用例 D：结构性反 AI

草稿包含漂亮句子、环境字幕、浅显心理和格言式段尾，但场面无变化。通过标准：

- 先指出场面运动问题；
- 不把主要工作变成禁词替换；
- 删除或重建无功能段落；
- 让转折影响后文；
- 净稿不附自评。

### 用例 E：失败后重建

用户连续两次指出同类错误。通过标准：

- 停止局部修补；
- 废弃旧骨架；
- 只保留确认事实和明确保留句；
- 重新定义场面性质变化；
- 不把旧稿中漂亮句子强塞回去。

## 3. 输出契约测试

| 请求 | 通过输出 | 失败输出 |
|---|---|---|
| “只给正文” | 纯净正文 | 前置分析、自评、来源卡 |
| “分析问题” | 问题-证据-影响-动作 | 未经要求直接重写 |
| “标出化用” | 正文与来源说明分开 | 只列书名；净稿夹内部笔记 |
| “只改两段” | 两段范围内最小必要修改 | 顺手改整章 |
| “不要新增设定” | 保持未知为空白 | 为完整性补人物背景 |

## 4. 质量评分

每项 0–2 分：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 任务边界 | 越界 | 基本遵守 | 严格遵守并识别阻塞 |
| 最新版本 | 混入旧稿 | 大体正确 | 完全以最新材料为准 |
| 技术诊断 | 只谈语感 | 定位部分层级 | 准确定位最高层级 |
| 原文查读 | 未读/假读 | 读片段 | 读上下文并建卡 |
| 实质转换 | 换皮 | 改一项变量 | 多项转换且因果成立 |
| 人物因果 | 来源驱动 | 基本成立 | 欲望、知识、回避均成立 |
| 场面运动 | 前后相同 | 局部变化 | 变化影响退出与余波 |
| 反 AI | 词表清理 | 兼顾结构 | 从结构、信息、人物到句法 |
| 可追溯 | 无来源 | 粗略列名 | 版本、场景、机制、风险完整 |
| 输出契约 | 夹带过程 | 基本符合 | 与用户需求完全一致 |

关键失败项：假装读过原文、恢复用户否定内容、越界改写、近似复刻可辨识原文。任一出现即不通过，不以总分抵消。

## 5. 回归测试

每次修改 Skill 后至少运行：

1. 一个应触发提示；
2. 一个不应触发提示；
3. 一个最新版本冲突用例；
4. 一个要求实际原文查读的用例；
5. 一个连续失败后必须重建的用例；
6. 一个只要净稿的输出契约用例。

记录失败发生在哪一层：触发描述、任务路由、参考读取、执行步骤、验收或输出契约。修复最小必要位置，再重复相同测试。
